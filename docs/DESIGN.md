# 設計（v0, 2026-11-13）

前提：クロノス統合引継書（2026-11-10）と CURRENT_POLICY。旧アプリ・旧コードは入手不可のため、
旧成績（C0 59→45→30件、旧D +47.99%等）は**参考として凍結**し、本システムは新基準 `chronos_v2` として作る。
旧結果への合わせ込みは行わない（過剰適合を避ける）。

## 方針（引継書から変えないこと）

- 反発候補を価格条件＋Chronos-2で抽出し、AIが企業・市場の文脈（織り込み、一過性/構造性、追加悪化、反対証拠）を推論して重大リスクを精査する。
- 減益率などの固定閾値で一律REJECTしない。数値は材料としてAIに渡す。
- TOPIXはAIがニュース・政策・景気・為替等を審査。TOPIXにChronos-2は使わない。
- 評価軸は大幅下落の検出感度、通過後の危険率、通過率・購入数、資金稼働率、DD。収益は補助。
- 研究・仮想運用のみ。自動発注しない。最終判断はユーザー。

## 全体構成

```
[取込] J-Quants v2（Standard＋TDnetアドオン）→ 生データ（版付き・追記のみ）
        → 正規化（available_at 付き Parquet / DuckDB）
  ① 銘柄群：時点ごとの適格判定（時価総額・売買代金・100株金額）。前向き名簿と過去評価用の層化抽出を分ける
  ② 候補抽出：価格条件＋Chronos-2（設定・モデルrevision・予測キャッシュを版管理）
  ③ 審査パケット：締切より前に available_at を持つデータだけで共通9項目を自動構成（漏洩ガード、ハッシュ）
  ④ AI審査：Claude API。企業AIと市場AIを分離。構造化出力。Web検索なし（パケットのみ）
  ⑤ 判断台帳：追記のみ。将来価格は凍結後に別ファイルで結合
  ⑥ バックテスト：口座（300万・3枠・100万上限・翌始値・20日・片道0.10%）＋感度/稼働率/無作為対照
  ⑦ 前向き運用：引け後バッチ、TDnet監視→再審査、メール通知、仮想約定
```

## AI審査のモデル構成（案）

| 工程 | 頻度 | モデル |
|---|---|---|
| TDnet開示の重要度分類・再審査要否 | 多 | Claude Haiku 5.5 |
| 書類ごとの事実抽出（数値は元データと機械照合） | 多 | Claude Haiku 5.5 |
| 候補ごとの最終リスク審査 | 少 | Claude Opus 5.5（Sonnet 5.5で足りるかは比較で決める） |

監査済み事例でHaiku/Sonnet/Opusを同一パケットで比較してから確定する。
過去事例はモデルが事後の結果を学習している可能性があるため、AI審査の評価は前向き運用を主とする。

## 評価の枠組み（2026-11-14 決定）

- 監視範囲：適格銘柄全体（約1,480社）。AI審査は候補のみ。
- 過去検証も各日の適格銘柄全体で行い、銘柄の人為的選択をしない。名簿の凍結は行わない。
- 旧研究の8銘柄は開発用として評価集計から除く（`is_dev_code`）。
- 期間：2016-11〜2021-10 を開発期間、2021-11以降を最終評価期間とする。
- AI審査の過去検証は候補から固定乱数で数百件を抽出して行う。
- 空き枠より候補が多い日の順位：A（C0の強さ＝予測リターン−基準）を主とし、B（下落の深さ）とR（無作為）を比較として常に併記（2026-11-14決定）。

## 研究の経過（2026-11-14〜15）

| 版 | 内容 | 結果の要点 |
|---|---|---|
| v2 | 価格条件＋Chronos C0 | 適格銘柄全体では口座で大損（無作為中央値 −27〜−54%）。普段の日の候補は期待値ほぼ0 |
| v3 | ＋相場条件（候補割合20%以上 or TOPIX20日−3%以下）＋リスク条件 | 期待値・急落率とも改善。ただし評価期間を見た後の設計。開発期間はほぼ横ばい |
| 旧8銘柄 | v2のまま8銘柄に限定 | 両期間でプラス（+66〜81%）。成績は銘柄選びに依存する仮説を支持 |
| v4 | ＋会社の質（3期連続営業黒字、ROE3年平均7%以上、自己資本比率45%以上、配当あり） | 8銘柄以外・評価期間で1回だけ検証（`config/strategy_v4.yaml`） |

C0（Chronos）は一貫した追加価値を示していない。評価期間は v3 の特徴について既に参照済みのため、最終確認は前向き運用で行う。
